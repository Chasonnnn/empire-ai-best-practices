## Users

All users associated with a Beta project should now have access to both the Beta and Alpha
clusters. Log in and familiarize yourself with the Beta environment and job submission process
before Service Unit (SU) accounting begins on October 1.

Documentation for submitting jobs and QoS/Service Unit tracking for both clusters is available
on the Empire AI FreshDesk support site. When using the examples in the attached guide, replace
`--account=YOUR_PROJECT_ACCOUNT` with the account associated with your PI/project (see the
PI-to-account reference).

## Storage

Home directories will have a 100 GB quota enforced. Any data currently stored on the cluster
that is not associated with an active Beta project should be offloaded. Each Beta project has
dedicated project storage at:

```
/projects/co/YOUR_PROJECT_ACCOUNT
```

All project-related files and datasets should be stored in this location rather than in your
home directory. Project storage is subject to SU charges at 8.333 SU per TB per month. Review
project storage regularly and remove or offload data that is no longer needed.

## Cluster

- NVL72 system stability: the NVL72 cluster has remained relatively stable over the past two
  weeks. A system status and alerting dashboard (Rootly System Status) provides current
  announcements and incident history.
- GPU scheduling strategy: single-GPU workloads are transitioning to the RTX 6000 Pro nodes on
  the Alpha cluster. Empire AI has implemented a minimum 4-GPU requirement for NVL72 jobs.
  Automated mechanisms are expected to terminate jobs that do not meet this requirement.
  Empire AI is also considering reserving four NVL72 trays for single-GPU jobs with very short
  wall times, along with support for interactive jobs, as a test-and-validate environment
  before scaling to larger NVL72 allocations.
- Alpha: scheduled maintenance September 21. Alpha transitions away from institution-specific
  partitions (`-p cornell`, `-p nyu`, ...) to a single hardware-tier partition named `alpha`
  and `grace`. Job submissions will require an explicit `--account` flag, aligning Alpha with
  the Beta scheduling model where users submit with their project account for SU accounting.
- Service Unit review: a dashboard will show SU balance; information will follow. PIs can
  review group usage on the ColdFront website.
